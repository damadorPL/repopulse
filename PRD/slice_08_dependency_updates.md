# Agent Implementation Slice 08: Dependency Checks & Update Pull Requests ("Dependencies")

## 1. Objective & Scope
RepoPulse tells users when the projects they **follow** ship. This slice adds the other direction: an independent
**Dependencies** module that checks the user's **own** repositories for outdated npm / Bun / PyPI dependencies, notifies
about them, and can open a pull request with the updated manifests **and regenerated lockfiles**.

* **Part A: Projects and checks (notify only).** A separate **Projects** list (`/dependencies`), independent of tracked
  repositories, with a one-click "Add from tracked repositories" picker. A new `deps-worker` service detects manifests,
  reads the resolved versions from lockfiles, asks the npm registry / PyPI for newer versions and stores the outdated
  set. Users get an in-app overview, SSE updates and notifications through their existing channels.
* **Part B: GitHub App.** The super admin registers a RepoPulse GitHub App (one-click manifest flow or manual
  form). Users install it on the repositories they want updated. The App gives scoped write access (contents + pull
  requests), short-lived tokens and bot-authored commits. It also lets RepoPulse read private repositories.
* **Part C: Update pull requests without lockfile regeneration.** Bump versions in manifests that need no resolver
  (`requirements*.txt` pins, including `--hash` lines; `package.json` / `pyproject.toml` without a lockfile). Commit to
  a `repopulse/deps/…` branch through the Git Data API and open or update one pull request per group.
* **Part D: Sandboxed lockfile regeneration.** A separate `deps-sandbox` service with no secrets, on an internal
  network whose only way out is an allowlist proxy (`deps-egress`) to the public registries. It runs the package
  manager in lockfile-only mode with scripts disabled and returns the new lockfile, which the worker validates and
  commits with the manifest change.
* **Part E (optional): GitHub App webhooks.** Rescan on pushes to the default branch and track PR merges / closes
  right away. Polling remains the fallback, so webhooks are never required.

Parts ship in order. Each part is usable on its own: after Part A every project works in notify-only mode; before
Part D, projects whose update needs a lockfile show "Create PR" disabled with the reason.

* **Prerequisites:** Slices 01–07 (0.8.0).
* **Ecosystems in scope:**

  | Ecosystem | Package manager | Manifest | Lockfile (read current versions) | Update PR |
  | --- | --- | --- | --- | --- |
  | npm | npm | `package.json` | `package-lock.json` (v2 / v3), `npm-shrinkwrap.json` | Part D (`npm install --package-lock-only`) |
  | npm | pnpm | `package.json`, `pnpm-workspace.yaml` | `pnpm-lock.yaml` (v9) | Part D (`pnpm install --lockfile-only`) |
  | npm | Bun | `package.json` | `bun.lock` (text, Bun ≥ 1.2) | Part D (`bun install --lockfile-only`) |
  | npm | Bun (binary lock) | `package.json` | `bun.lockb`: not readable, so the declared range is used | **check only**, with the hint "switch to the text `bun.lock`" |
  | npm | Yarn | `package.json` | `yarn.lock` (classic and Berry) | **check only** in this slice |
  | npm | none | `package.json` without a lockfile | — | Part C (manifest only) |
  | PyPI | pip | `requirements*.txt`, `requirements/*.txt`, `constraints*.txt` | the `==` pins are the lock | Part C (text edit + hashes) |
  | PyPI | uv | `pyproject.toml` (PEP 621 + PEP 735 groups) | `uv.lock` | Part D (`uv lock --upgrade-package`) |
  | PyPI | Poetry | `pyproject.toml` (`[tool.poetry.*]` or PEP 621) | `poetry.lock` | Part D (`poetry lock`) |
  | PyPI | none | `pyproject.toml` without a lockfile | — | Part C (manifest only) |
  | PyPI | pip-tools | `requirements.in` + compiled `.txt` (`autogenerated by pip-compile` header) | the compiled `.txt` | **check only** |

* **Out of Scope:**
  * Transitive dependencies (only direct dependencies are checked, as `npm outdated` does), security advisories
    (OSV / GitHub Advisory DB: a natural follow-up slice), license checks.
  * Other ecosystems (Go, Cargo, Maven, Composer, Docker images, GitHub Actions versions: the last one also needs the
    `workflows` App permission).
  * Private registries, scoped registries and registry auth from `.npmrc`, `.yarnrc.yml`, `pip.conf` or Poetry
    sources. Dependencies resolved from a non-default registry are reported as `UNSUPPORTED_SOURCE`.
  * `git:`, `file:`, `link:`, `workspace:`, URL and path dependencies, pnpm `catalog:` entries, npm `overrides` /
    pnpm `overrides` / Yarn `resolutions` (skipped, listed as `UNSUPPORTED_SOURCE`).
  * Auto-merge, running the project's tests (the repository's own CI runs on the PR), rebasing on review comments.
  * Lockfile regeneration for Yarn, `bun.lockb` and pip-tools.

### Design constraints
* **Independent module.** The feature lives in its own package (`@repopulse/deps`) and its own services
  (`deps-worker`, `deps-sandbox`, `deps-egress`). The existing `worker` gains nothing. The module touches existing code
  only through: the schema, the `@repopulse/github` / `@repopulse/queue` / `@repopulse/notifications` packages
  (new exports, no behavior changes), web pages and actions, and a new `events` field on `NotificationRule`. With
  the module disabled in Admin, or `deps-worker` not deployed, the rest of RepoPulse is unchanged.
* **Projects are per user, and separate from subscriptions.** A `DependencyProject` belongs to one user, unique on
  `(userId, githubRepoId)`. It may link to a tracked `Repository` (`repositoryId`, `SetNull`) for the quick-add
  picker and a "Tracked" badge, but neither list depends on the other: removing a subscription keeps the project,
  and the reverse.
* **One PR owner per GitHub repository.** Two users may both check the same repository, but only one project per
  `githubRepoId` instance-wide may open PRs (`DependencyPrOwner`, primary key `githubRepoId`). Otherwise two RepoPulse
  users would race on the same branches. The second user can still use notify mode, and the UI names who owns PRs.
* **Untrusted repository content never runs in a process that holds secrets.** `deps-worker` (database, Redis, App
  private key, installation tokens) only parses files with pure TypeScript and edits text. Everything that runs a
  package manager runs in `deps-sandbox`, which gets the files over HTTP and has no tokens, no database, no Redis and
  no general internet access.
* **The bot writes only what it planned.** A PR commit may change only the manifest and lockfile paths of the group.
  The worker re-parses every rewritten file and checks that only the planned values changed. Lockfiles from the
  sandbox are size-capped and parsed, and the input lockfile format version must be kept. Anything else aborts the job.
* **Every query is scoped to the signed-in user** (rule 1). Admin settings are super admin only (rule 2). App
  secrets are encrypted with `encryptToken` (rule 6). No new feed / unread semantics: dependency updates are not
  `Release` rows and never appear in the release feed.
* **Supply-chain care by default.** Versions newer than `minReleaseAgeDays` (default 3) are held back (`TOO_NEW`),
  deprecated and yanked versions are never targets, and pre-releases are targets only when the project opts in and
  the current version is itself a pre-release of the same line.

### Step 3.2: Detection and parsing (`@repopulse/deps`, pure)
1. **`detectManifests(tree, opts)`** takes the default-branch tree from `fetchRepoTree` (already capped at 10,000
   entries) and returns manifest groups:
   * Skip `node_modules/`, `.venv/`, `venv/`, `vendor/`, `dist/`, `build/`, `.git/`, and any directory named
     `fixtures`, `__fixtures__`, `testdata` or `examples`. Unless `manifestPaths` is set, use at most
     `MAX_MANIFESTS_PER_PROJECT` (25), shallowest first, and add a warning when some were dropped.
   * **npm family:** a `package.json` is a workspace member when an ancestor `package.json` lists it in `workspaces`
     or a `pnpm-workspace.yaml` lists it in `packages`. Members share the root's lockfile and package manager, and
     their PRs regenerate the root lockfile. Package manager, in order: the `packageManager` field, then which
     lockfile exists in the root (`pnpm-lock.yaml` > `bun.lock` > `bun.lockb` > `yarn.lock` > `package-lock.json`),
     then `NONE`.
   * **PyPI family:** `pyproject.toml` with `[tool.poetry]` or `poetry.lock` → `POETRY`; with `uv.lock` or
     `[tool.uv]` → `UV`; otherwise `NONE`. `requirements*.txt`, `requirements/*.txt` and `constraints*.txt` → `PIP`,
     or `PIP_TOOLS` when the file starts with the `pip-compile` header (then the matching `.in` is the declared spec
     and the `.txt` pin is the current version).
2. **`parsePackageJson(text)`**: `dependencies` (PROD), `devDependencies` (DEV), `peerDependencies` (PEER, reported
   but never bumped beyond the declared range), `optionalDependencies` (OPTIONAL). Specs that are not semver ranges
   (`git+`, `github:`, `file:`, `link:`, `workspace:`, `catalog:`, URLs, `npm:` aliases, `*`, `latest`) →
   `UNSUPPORTED_SOURCE`. Each entry keeps the **byte span of its value string** for the rewrite step.
3. **`parseRequirements(text)`**: PEP 508 lines with extras and markers, `\` continuations, `--hash=sha256:` options,
   comments; `-r` / `-c` includes are followed within the repository (cycle-safe, depth 5). `-e`, URLs, `--index-url`
   / `--extra-index-url` (the whole file becomes `UNSUPPORTED_SOURCE` for packages not on PyPI) are recorded, not
   rewritten.
4. **`parsePyproject(text)`**: parse with `smol-toml` (pin the version) for values. Spans are found with a small
   tokenizer over the same text (string literals inside the located array / table), because TOML parsers do not
   expose positions. Tables: `[project] dependencies`, `[project.optional-dependencies]`, `[dependency-groups]`,
   `[tool.poetry.dependencies]`, `[tool.poetry.group.<g>.dependencies]` (string or `{ version = "…" }` forms).
   `python` in Poetry tables is the interpreter, not a dependency. `requires-python` is kept to filter PyPI releases.
5. **Lockfile readers** return `Map<name, version>` for direct dependencies of the given importer:
   `package-lock.json` (`packages["node_modules/<name>"]`, nested workspace paths), `pnpm-lock.yaml`
   (`importers[<path>].dependencies[name].version`, peer suffix stripped), `bun.lock` (JSONC with trailing commas,
   `packages[name][0]` = `"name@version"`), `yarn.lock` (classic: `name@range:` blocks; Berry: YAML with
   `resolution`), `uv.lock` and `poetry.lock` (TOML `[[package]]`). A file larger than `MAX_LOCKFILE_BYTES` (20 MiB),
   or one that fails to parse, gives an empty map and a warning, and the scan goes on.

### Step 3.3: Versions
1. **npm** (`versions/npm.ts`): `semver` (already used by `@repopulse/github`). `maxSatisfying(versions, declared)`
   → `wantedVersion`; `bumpRange(declared, target)` keeps the operator style: `1.2.3` → `1.4.0`, `^1.2.3` →
   `^1.4.0`, `~1.2.3` → `~1.2.9`, `>=1.2.3` → `>=1.4.0`, `1.x` / `^1` → `2.x` / `^2` for a major. A compound range
   (`>=1 <3`, `||`) is not bumped: it becomes `BLOCKED_BY_RANGE` when the target is outside it.
2. **PEP 440** (`versions/pep440.ts`): write it here (small, fully unit-tested) rather than add a dependency. It covers
   epochs, pre / post / dev releases, local versions, and specifiers `== != <= >= < > ~= ===` plus `==1.*`. It also
   handles Poetry `^` / `~` constraints (same semantics as npm caret / tilde). `bumpSpecifier`: `==1.2.3` → `==1.4.0`,
   `~=1.2` → `~=1.4`, `>=1.2` → `>=1.4` (only with `BUMP`), Poetry `^1.2` → `^1.4`. An upper bound that excludes the
   target (`<2`, `!=…`) → `BLOCKED_BY_RANGE`.
3. **`classifyUpdate(current, target)`** → `SemverType`, using the same thresholds as `classifySemver` (`MAJOR` when
   the major changes, or the minor for `0.x`). When `currentVersion` is unknown, the lower bound of `declared` is
   used.

### Step 3.4: Registries (`@repopulse/deps`, fetch injected for tests)
1. **npm**: `GET https://registry.npmjs.org/<name>` with `Accept: application/vnd.npm.install-v1+json` (the
   abbreviated packument: versions, `dist-tags`, `deprecated`). It lacks publish times, so the full document's
   `time` is fetched only when the min-age policy needs it and the abbreviated `modified` is newer than the cache.
   Scoped names are encoded as `@scope%2Fname`. Keep `repository.url` → `sourceRepoUrl` when it is a GitHub URL.
2. **PyPI**: `GET https://pypi.org/simple/<normalized>/` with `Accept: application/vnd.pypi.simple.v1+json`
   (PEP 691). This gives the `versions` list, and for each file `upload-time` (PEP 700), `yanked`, `requires-python`
   and `hashes.sha256`. A version's release date is its earliest file upload. A version is a candidate only if some
   file's `requires-python` overlaps the project's `requires-python`. `GET https://pypi.org/pypi/<name>/json` is used
   only for `project_urls` (→ `sourceRepoUrl`).
3. **Cache** (`RegistryCache`): the worker stores each response body and ETag in Redis under `deps:reg:<eco>:<name>`
   for `REGISTRY_CACHE_TTL_MS` (1 h). After that it revalidates with `If-None-Match`. Never more than
   `REGISTRY_CONCURRENCY` (8) requests in flight per scan. A 404 → `UNSUPPORTED_SOURCE` ("not on the public
   registry"). A 429 / 5xx → retry the whole scan job with backoff, keeping the previous results.
4. Registry hosts are fixed constants. No user-supplied URL is ever fetched, so the SSRF guard is not involved.

### Step 3.5: Planning (`plan.ts`, pure)
`selectTarget(candidates, dep, policy, now)`, in order:
1. Drop deprecated, yanked, prerelease (unless `includePrereleases` and the current version is a prerelease of the
   same `major.minor`), and `requires-python`-incompatible versions.
2. Ignore rules: `name` is a glob with `*` only at the start and/or end (like the Slice 07 tag patterns; zod rejects
   others). `versions` is an optional range in the ecosystem's syntax. A rule without `versions` → `IGNORED`.
3. `newest` = highest remaining version above current. None → the row is deleted (up to date).
4. Above `maxUpdateLevel`: target the newest version **within** the level if one exists (`OUTDATED`). The row still
   shows `latestVersion`, so the UI can say "2.0.0 available, outside your policy". Otherwise `ABOVE_LEVEL`.
5. Younger than `minReleaseAgeDays`: fall back to the newest older-than-age version that is still above current.
   Otherwise `TOO_NEW`.
6. With `LOCKFILE_ONLY`, a target outside `declared` → `BLOCKED_BY_RANGE`. In range → `OUTDATED` (lockfile-only PR).
7. A target equal to a `DISMISSED` version stays `DISMISSED`. A newer one becomes `OUTDATED` again.

`groupUpdates(outdated, groupMode)` → `{ groupKey, updates }[]`, deterministic order:
* `SINGLE`: one `all` group per project.
* `SEPARATE_MAJORS`: one `all` group for patch + minor, plus `major-<slug(name)>` per major update.
* `PER_DEPENDENCY`: `<eco>-<slug(name)>` per dependency name (all manifests that use it move together).
* Only the first `maxOpenPrs` groups (majors last) get PRs. The rest wait for a slot.

### Step 3.6: `deps-worker` service (`apps/deps-worker`)
Same structure, logger, `deps` injection and shutdown as `apps/worker` ([docs/worker.md](../docs/worker.md)). Health
on `DEPS_HEALTH_PORT` (3002). Every 30 s it writes a Redis heartbeat `deps:worker:heartbeat` (TTL 90 s). The web
app reads it to show "Dependency checks are not running".

| Queue (`DEPS_QUEUE_NAMES`) | Payload | jobId | Concurrency | Options |
| --- | --- | --- | --- | --- |
| `deps-scheduler` | `{}` | repeatable `deps-scheduler-cron` (`DEPS_SCAN_CRON`, default `17 * * * *`) | 1 | removeOnComplete |
| `deps-scan` | `{ projectId, trigger: "add" \| "schedule" \| "manual" \| "webhook", requestedByUserId? }` | `deps-scan-{projectId}` | `DEPS_SCAN_CONCURRENCY` (3) | 3 attempts, exp. 60 s; priority manual / add 1, others 10; removeOnComplete/Fail |
| `deps-update` | `{ projectId, groupKey, trigger: "manual" \| "auto" }` | `deps-update-{projectId}-{groupKey}` | `DEPS_UPDATE_CONCURRENCY` (1) | 2 attempts, exp. 120 s; removeOnComplete/Fail |
| `deps-notify` | `{ ruleId, projectId, kind: "digest" \| "pull_request", scanId \| prId }` | `deps-notify-{ruleId}-{scanId \| prId-state}` | 5 | 3 attempts, exp. 5 s; kept 7 days for dedup |

Group keys contain only `[a-z0-9-]` (slugified), so jobIds never contain `:` (BullMQ rejects it).

**Scheduler:** projects with `scanStatus != SCANNING` (or stale after 15 min) and `nextScanAt <= now`, batches of
200. Nothing runs while `InstanceSettings.depsEnabled` is false.

**Scan (`processDepsScan`):**
1. Load the project and its owner. Pick a read token (`github-access.ts`): the installation token when the App is
   installed on the repo, else the owner's OAuth token (public repos), else anonymous. A private repo without the App
   → `scanError = "Install the GitHub App to check private repositories"`, `ERROR`, no retry.
2. `fetchRepoTree` (default branch) → refresh `fullName`, `defaultBranch`, `isPrivate`, `lastScannedSha`.
   `detectManifests`. Read changed blobs only (`blobSha` differs) with `readBlobs`, each capped at
   `MAX_MANIFEST_BYTES` (1 MiB) and lockfiles at 20 MiB.
3. Parse, look up every distinct `(ecosystem, name)` once, `selectTarget` per dependency. Cap: at most
   `MAX_DEPENDENCIES_PER_PROJECT` (1,000) checked, with a warning beyond that.
4. One transaction: upsert manifests (delete vanished ones, which cascades their updates), upsert / delete
   `DependencyUpdate` rows. Keep `firstSeenAt` / `notifiedAt` when `targetVersion` is unchanged, and reset both when
   it changes. Set `lastScannedAt`, `nextScanAt = now + scanIntervalHours`, `scanStatus = IDLE`, `errorCount = 0`.
5. Refresh open PR states (`getPullRequestState`): merged → `MERGED`; closed → `CLOSED` and its targets'
   rows `DISMISSED`; a branch head ≠ `headSha` that the bot did not write → `EDITED` (notified once, never touched
   again).
6. After commit: SSE `DEPS_SCAN_COMPLETED { projectId, fullName, outdated, majors }` to the owner. Notifications
   (§3.11). With `AUTO_PR` and the App usable, enqueue `deps-update` for each group whose planned targets differ from
   its open PR's `targets` (or that has no PR yet), within `maxOpenPrs`.
7. Errors: GitHub 404 → `ERROR` + `errorCount++`, paused after 5 (like repo polling). GitHub rate limit →
   `queue.rateLimit(reset)` + `Worker.RateLimitError()`. Anything else is rethrown (BullMQ retries), and only the last
   attempt counts. A manual scan's failure publishes `DEPS_SCAN_FAILED` with the user-safe message.

Read the Next.js 16 docs in `node_modules/next/dist/docs/` for dynamic segments and route handlers before writing the
pages. Every page uses `requireUser()`; the admin pages use `requireSuperAdmin()`. When `depsEnabled` is false, the
sidebar link is hidden and `/dependencies` shows "Dependency checks are turned off by the administrator".

1. **`/dependencies` (list):** one row per project: avatar, `fullName` (links to the detail page), package-manager

   "Tracked" badge when `repositoryId` is set. Search + sort (`name`, `outdated`, `checked`) kept in the URL like

2. **Add dialog (two tabs):**
   * **From tracked repositories** (default tab): a searchable checklist of the user's subscriptions that are not

3. **`/dependencies/[owner]/[name]` (detail):** canonical-casing redirect like Slice 07, `notFound()` when it is not

   * **Header:** repo, default branch, last check + "Check now", App status banner: "Not installed: install the

   * **Pull requests:** planned groups with "Create PR" / "Update PR" (disabled with a reason: no App, no write

   * **Settings** (form, `updateDependencyProjectSettingsAction`): mode, max level, pre-releases, min release age,

   * **Manifests:** detected files with package manager, lockfile, dependency count and warnings.
   * **Danger zone:** remove the project (also releases PR ownership; open PRs stay on GitHub).
4. **Repository settings page** (`/repositories/[owner]/[name]`): a small "Dependencies" card with "Check this
   repository's dependencies" (adds the project), or a summary + link when it already is one.
5. **Notifications settings:** each rule gets event checkboxes: Releases, Dependency updates, Dependency pull
   requests. A rule scoped to a tag supports only Releases (projects have no tags); the form disables the other two.
6. **Admin → GitHub App** (`/admin/github-app`, Part B, §3.8) and **Admin → Dependencies** (`/admin/dependencies`):

   heartbeat payload), project / open-PR counts. Both are added to `ADMIN_SECTIONS`.
7. **SSE:** `DEPS_SCAN_COMPLETED` / `DEPS_SCAN_FAILED` / `DEPS_PULL_REQUEST_UPDATED` → toast + `router.refresh()` in
   `sse-listener.tsx`. Update `parseRealtimeEvent` and `events.test.ts`.

**Server Actions** (`server/actions/dependencies.ts`, all `ActionResult<T>`, zod `.strict()`, `toActionError`):
* `addDependencyProjectsAction({ sources: ({ subscriptionId } | { repoUrlOrSlug })[], updateMode })`, 1–20 sources.
  A `subscriptionId` must belong to the user. At most `MAX_DEPENDENCY_PROJECTS_PER_USER` (50). It fetches the repo with
  the user's token before the transaction. A private repo needs the App and the user's read permission. Existing

* `removeDependencyProjectAction({ projectId })`.
* `updateDependencyProjectSettingsAction({ projectId, …fields })`. Switching to a PR mode claims `DependencyPrOwner`

* `triggerDependencyScanAction({ projectId })`, with a 5-minute cooldown on `lastScannedAt` like manual repo sync.

* `createDependencyPullRequestAction({ projectId, groupKey })`: re-checks mode ≠ `NOTIFY`, PR ownership and App

* `ignoreDependencyAction({ projectId, name, versions? })` / `removeIgnoreRuleAction`: rewrite `ignoreRules` and

### Step 3.8: GitHub App (Part B)
1. **Creation (manifest flow, preferred):** Admin → GitHub App → "Create GitHub App" (optional organization field).
   The page posts a form to `https://github.com/settings/apps/new?state=<s>` (or
   `/organizations/<org>/settings/apps/new`). `state` is a random value in an httpOnly, `sameSite=lax`, 10-minute
   cookie. The manifest:
   ```json
   {
     "name": "RepoPulse (<host>)",
     "url": "<APP_BASE_URL>",
     "redirect_url": "<APP_BASE_URL>/api/github-app/manifest/callback",
     "setup_url": "<APP_BASE_URL>/dependencies?installed=1",
     "setup_on_update": true,
     "public": true,
     "hook_attributes": { "url": "<APP_BASE_URL>/api/github-app/webhook", "active": false },
     "default_permissions": { "metadata": "read", "contents": "write", "pull_requests": "write" },
     "default_events": []
   }
   ```
   `public: true` lets other users and organizations install it; that is still gated by RepoPulse access. Webhooks
   start inactive (Part E turns them on). The callback route (super admin only, checks `state`) calls
   `convertAppManifest(code)` (`POST /app-manifests/{code}/conversions`). It stores id, slug, client id, owner, the
   encrypted PEM and the encrypted webhook secret, then redirects to the admin page.
2. **Manual form** (fallback for GitHub Enterprise-like setups or existing Apps): App id, slug and the private key
   PEM (validated by signing a JWT and calling `GET /app`). `saveGitHubAppSettingsAction` /
   `removeGitHubAppSettingsAction` use `getSuperAdminOrThrow()`. The view model never contains the key or the
   secret, only "Key saved".
3. **Tokens** (`@repopulse/github/app.ts`, using `@octokit/auth-app`, pinned): `getRepoInstallation(owner, repo)`
   (`GET /repos/{o}/{r}/installation`, App JWT; 404 = not installed). `createInstallationToken(installationId,
   { repositoryIds: [githubRepoId], permissions })` narrows each token to the one repository, with `contents: read`
   for scans and `contents: write` + `pull_requests: write` for updates. Tokens are cached in `deps-worker` memory
   only, until 5 minutes before expiry, and never stored or logged.
4. **User access:** RepoPulse never takes the installation's word for who may use it. Before a project is added
   (private repo) and before **every** `deps-update` job, `getCollaboratorPermission(owner, repo, githubLogin)` with
   the installation token must return `write`, `maintain` or `admin` for updates (`read`+ for private-repo checks).
   A project whose owner lost access falls back to `NOTIFY`, and the owner is notified once.
5. The installation flow needs no callback trust: `setup_url` just lands on `/dependencies`, and the next scan (or a
   "Check again" button) discovers the installation per repository.

### Step 3.9: Update pull requests (Part C; lockfile step added by Part D)
`processDepsUpdate`:
1. Load the project; `NOTIFY` mode, no `DependencyPrOwner` row for it, no App installation, or failed permission
   check (§3.8.4) → `UnrecoverableError` with a user-safe `scanError`-style message, shown on the PR card.
2. Get the default-branch head and tree. Recompute the group from the stored rows plus fresh registry data, so a PR
   never sets a version the policy rejects now. Empty group → close the open PR with a comment ("All updates in this
   group were applied or are no longer wanted"), state `CLOSED`, done.
3. Rewrite the manifests (`rewrite/*`): span edits only. Re-parse and compare with the plan: every planned
   dependency has its new spec and nothing else differs. Keep the file's line endings and the trailing newline.
4. `requirements*.txt` with hashes: replace the `--hash` set of each bumped line with the sha256 of **every** file
   of the target version from the Simple API (what `pip-compile --generate-hashes` emits). Keep the continuation
   layout.
5. Lockfile needed (any manager except `NONE` / `PIP`):
   * Before Part D: abort with `LOCKFILE_UPDATE_UNAVAILABLE` (the UI disables the button for these projects anyway).
   * Part D: call the sandbox (§3.10) with the rewritten manifests, the current lockfile and the workspace files.
     Validate the response: only the expected lockfile path, ≤ 20 MiB, parses, the same `lockfileVersion` /
     `lock-version` / format as the input, and every planned dependency resolves to its target (read back with the
     §3.2 readers). Otherwise abort with the sandbox's sanitized stderr tail (≤ 2 KB) in the job log, never in the PR.
6. Branch `repopulse/deps/<groupKey>`:
   * It exists and its head ≠ `headSha` → `EDITED`, stop. The bot never overwrites someone else's commits.
   * It exists and its tree already equals the new content for these paths → no-op (refresh the PR body only).
   * Otherwise `commitFiles` creates blobs → tree (`base_tree` = default head) → commit (parent = default head,
     message `"<commitPrefix> update react to 19.3.0"` or `"<commitPrefix> update 7 dependencies"`, no
     author / committer fields, so GitHub attributes it to `<slug>[bot]`) → create the ref, or force-update it (the
     branch is bot-owned per the check above).
7. `upsertPullRequest`: title = commit subject. Body (`pull-request.ts`): a table (dependency, manifest, from → to,
   level, released, changelog link), notes for skipped updates in the group, and a footer "Opened by RepoPulse ·
   settings: <project URL>" with a hidden marker `<!-- repopulse:deps:<groupKey> -->`. No mentions, no
   auto-merge, no labels (the App has no `issues` permission).
8. Save `DependencyPullRequest` (`headSha`, `targets`, `state = OPEN`). SSE `DEPS_PULL_REQUEST_UPDATED`. Notify
   (`DEPENDENCY_PULL_REQUESTS`) when the PR is opened, and when it is updated with new versions (not for no-op
   refreshes).
9. Rate limit → `rateLimit` + `RateLimitError` as in the scan. A 409 / 422 from the ref update (race with a push) →
   retry once from step 2.

### Step 3.10: Sandbox (Part D: `apps/deps-sandbox`, `deps-egress`)
1. **Contract** (`sandbox-contract.ts`, zod-validated on both sides): `POST /v1/lock`, `Authorization: Bearer
   <DEPS_SANDBOX_TOKEN>`, body `{ packageManager, workdir, files: { path, contentBase64 }[], upgrade: { name,
   version }[], expectLockfile }`. Total body ≤ 30 MiB, ≤ 2,000 files (workspace manifests only, no source code).
   Response `{ ok: true, lockfile: { path, contentBase64 } }` or `{ ok: false, code, stderrTail }`.
2. **Execution** (`run-lock.ts`): one job at a time (503 `BUSY` otherwise; the worker retries). A fresh `mkdtemp`
   dir under a tmpfs, removed afterwards. It runs as the unprivileged `sandbox` user with a minimal env:
   `HOME=<tmp>/home`, `PATH`, `HTTP(S)_PROXY=http://deps-egress:3128`, `CI=1`, `npm_config_ignore_scripts=true`,
   `UV_NO_BUILD=1`, no `*_TOKEN`. The child is killed after `DEPS_SANDBOX_TIMEOUT_MS` (300,000) and output is capped
   at 1 MiB. Before running, it deletes repository-level config that can redirect registries or run code: `.npmrc`,
   `.yarnrc*`, `.pnpmfile.cjs`, `bunfig.toml`, `pip.conf`, `poetry.toml`, `uv.toml` and `[tool.uv.index]` /
   Poetry `[[tool.poetry.source]]` entries. When those entries existed, the result is `UNSUPPORTED_REGISTRY`.
3. **Commands** (`commands.ts`, verify each flag against the pinned tool version during implementation and test it in
   `run-lock.test.ts` with fixture projects):

   | Manager | Command (cwd = workspace root) |
   | --- | --- |
   | npm | `npm install --package-lock-only --ignore-scripts --no-audit --no-fund` |
   | pnpm | `pnpm install --lockfile-only --ignore-scripts --ignore-pnpmfile` |
   | Bun | `bun install --lockfile-only --ignore-scripts` |
   | uv | `uv lock --upgrade-package <name>==<version> …` (one flag per upgrade) |
   | Poetry | `poetry lock` (Poetry 2: keeps unrelated locked versions) |

   With `LOCKFILE_ONLY` (ranges unchanged), npm uses `npm update <name>… --package-lock-only` and pnpm uses
   `pnpm update <name>… --lockfile-only`. Tool versions: the image pins the current major of each tool. A project that
   needs another major (the `packageManager` field, pnpm `lockfileVersion`, Poetry `lock-version`) gets
   `UNSUPPORTED_TOOL_VERSION`, never a lockfile in a different format. Corepack is disabled, because downloading
   arbitrary tool versions would widen the egress allowlist.
4. **Network:** compose network `deps_sandbox` with `internal: true` holds `deps-sandbox` and `deps-egress`.
   `deps-egress` is also on the default network. `deps-worker` is on both. `deps-egress` is a pinned Squid image whose
   `squid.conf` allows only `CONNECT` to `registry.npmjs.org`, `registry.yarnpkg.com`, `pypi.org` and
   `files.pythonhosted.org` on 443, and denies everything else (including private address ranges). Verify that
   Coolify keeps a custom `internal` network as declared; if it does not, document the fallback (a host firewall
   rule) in `docs/deployment.md`.
5. **Container hardening** (compose): `read_only: true`, `tmpfs: /tmp:size=2g`, `cap_drop: [ALL]`,
   `security_opt: [no-new-privileges:true]`, `pids_limit: 512`, memory 2 GiB, CPU 2. No volumes, no
   `env_file`, and `DEPS_SANDBOX_TOKEN` is the only variable passed in. `GET /health` (no auth) → `{ status: "ok",
   tools: { npm, pnpm, bun, uv, poetry } }`.

### Step 3.11: Notifications
1. **Digest after a scan:** when a scan produces `OUTDATED` rows with `notifiedAt = null` at or above the project's
   `notificationLevel` (same `passesNotificationLevel` semantics as Slice 07, applied to `level`), queue one
   `deps-notify` per enabled rule of the owner that has `DEPENDENCY_UPDATES` in `events` and no tag. Then set
   `notifiedAt` on those rows in the same transaction as the job records. The first scan of a new project sends a
   digest only when the user ticked "Notify about what is outdated now" in the Add dialog (default off), so adding 20
   projects doesn't flood the channels.
2. **PR events:** opened / updated with new versions / edited by someone else / owner lost access → rules with
   `DEPENDENCY_PULL_REQUESTS`.
3. **`@repopulse/notifications`:** `dispatchDependencyNotification(input, opts)` with structural input (`{ project:
   { fullName, url }, kind, updates: { name, from, to, level, manifest }[], pullRequest? }`). It reuses the channel
   senders, the SSRF guard and the SMTP transport, and adds a formatter per channel: Discord embed (color by highest
   level), Slack blocks, ntfy / Gotify Markdown (priority high when a major is present), email table, and custom
   webhook `{ event: "dependencies.outdated" | "dependencies.pull_request", repository, updates, pullRequest, links
   }` with `X-RepoPulse-Event`. A digest lists at most 25 updates plus "and N more". Links go to the project page.
   Keep it independent of `@repopulse/db` (package rule).
4. `deps-notify` re-checks before sending: the rule still exists, is enabled and has the event, the project still
   exists, and the project's level / mode still allow it → otherwise `SKIPPED`. Errors are classified like
   `notification-dispatch`.

## 5. Decisions taken (confirm or change before implementing)
1. **Write access through a GitHub App**, created by the super admin (manifest flow) and installed per repository by
   users. Sign-in scopes stay `read:user user:email`.
2. **Changes land as a branch + pull request**, never as direct commits to the default branch.
3. **Lockfiles are regenerated in a sandbox** with no secrets and allowlisted egress (Part D). Until then, PRs are
   offered only where no lockfile is involved.
4. **Projects are a separate list**, with quick add from tracked repositories (and from the repository settings
   page). Projects are per user; only one project per GitHub repository may open PRs.
5. Defaults chosen here, easy to change: notify-only on add, `maxUpdateLevel = MINOR`, `minReleaseAgeDays = 3`,
   `SEPARATE_MAJORS` grouping, `BUMP` range strategy, daily scans, direct dependencies only, Yarn / `bun.lockb` /
   pip-tools check-only, public registries only, no auto-merge.
